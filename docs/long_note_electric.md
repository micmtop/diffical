# 长音「电音」诊断（2026-11-14）

## 结论（先看这段）
长音电音不是模型装配、不是旧画布、也不是声码器：
**恒定音高的长音，输出频谱几乎是冻结的**；渲染器只是忠实搬运源录音里那一小段
本来就静止的稳态。听起来就像持续嗡鸣/风琴音，即「电音」。

## 证据
案例：`artifacts/mel-handover-v2/cases/captured-teto-three-notes.json`
（3 个 1000ms 音，tone 60/64/67，F0 均值 295/360/392Hz）

拉长参数（`DIFFICAL_STRETCH_DEBUG=1` 可复现）：
```
[stretch] - あ  src=497ms tgt=709ms ratio=1.43
[stretch] a あ src=694ms tgt=666ms ratio=1.00
[stretch] a あ src=694ms tgt=906ms ratio=1.31
```
没有一个触发 >2.5× 的长音分支；第 3 音只把源文件 `[3.077, 3.771]s` 线性映射到 906ms。

累计谱变化（前 100ms 均值 vs 后 100ms 均值，log-mel）：

| 片段 | 0.8s 内累计谱变化 |
|---|---|
| 自然长元音（同一源文件 0.2–1.4s 窗口） | 4.25 |
| 自然长元音（同一源文件 1.5–2.3s 窗口） | 1.72 |
| 源文件实际使用的 `[3.077,3.771]s` | **0.54** |
| legacy 第 3 音稳态（392Hz 恒定） | **0.22** |
| 模型 第 3 音稳态（同段） | **0.37** |
| legacy/模型 第 1 音（有滑音/颤音） | 2.08 / 2.05 |

- 有音高起伏的音（第 1 音）谱运动正常；恒定音高的第 3 音冻结。
- 渲染器把源区间（0.54）搬运成 0.22–0.37，是**忠实**的，不是额外抹平；
  后处理平滑函数未调用（`_smooth_inter_frame_transitions` 只有定义，无调用点）。
- 源文件 3.90s 后是静音；可用元音区 `[3.077,3.90]` 的额外运动主要来自**收尾衰减**
  （3.77→3.90 能量 0.16→0.0015），拿来做保持会变成「长音渐弱」，不合适。

## 已排除
- **声码器往返**：真实长元音 → mel → ONNX 声码器重建，HNR 26.36→24.99 dB、
  谱平坦度 0.015→0.019、能量调制峰 36.8Hz 强度 1.0→1.1（无帧率嗡鸣）。
- **模型装配 vs 旧画布**：同一长音两者谱运动 0.37 vs 0.22，差别很小；
  F0 曲线输出相同（f0_unchanged）。
- **接缝过渡**：接缝跳变与长音电音是两件事；k0/k2/k3 听不出差别，过渡保持默认关闭。

## 可用的三条路（需要你听完 A/B 后定）
1. **音高微起伏**（实验文件里的 E1/E3）：恒定音高处加 ±30 音分/5.2Hz 颤音，
   立刻「活」起来。但这等于替用户生成 F0，和「F0 必须来自 IRender 曲线」的约束冲突，
   只能作为对照/需要你明确同意才能进生产。
2. **慢谱倾斜漂移**（E2/E3）：不改 F0，只在 mel 上叠 ±0.55 的慢倾斜（0.3Hz），
   让频谱不冻结。属于「合成细节」，同样需要你确认可接受。
3. **模型重训（推荐、与架构一致）**：训练对的瑕疵分布加入「长音拉伸」
   （把目标自己的切片拉伸 1.5–6× 当输入，目标仍是原录音），让模型学会从静止片段
   重建自然演化；顺带解决接缝大跳变（当前训练只有 ±2 帧偏移、0.85–1.15 拉伸）。
   需要 GPU 训练（远程 2060M），并重跑 `tests/test_algorithm_audit.py`
   与 `tests/test_dataset_audit.py`。

## 回归审计（2026-11-14，搬迁到 neo 后）
`tests/test_algorithm_audit.py`（脚本里 C/D 硬编码 `train/ckpt_cp/last.pt`，不是生产权重）：

| 项 | ckpt_cp（脚本默认，旧） | ckpt_gan（生产） |
|---|---|---|
| A 零瑕疵装配=目标 | PASS 0.001055 | PASS |
| B 目标可达性 | PASS | PASS |
| C 内容保真 ≥0.8 | PASS 0.825 | **PASS 0.884** |
| D 接缝 ≤ 硬切 50% | FAIL 0.663 | **FAIL 0.766**（只降 23%） |
| E 帧归属对齐 | PASS | PASS |
| F 淡化归一 | PASS | PASS |

`tests/test_dataset_audit.py`：3/4 PASS；FAIL 项「接缝错误集中」实测 1.71×
（阈值 ≥2× 内部误差），属既有阈值未达。

**含义**：模型在留出集上确实只把接缝跳变消掉约 23%，审计 D 的 ≤50% 目标未达到。
这和真实案例里「输入接缝 1.84–2.19 → 输出 1.49–1.82」一致。重训时建议：
- 接缝瑕疵加大（偏移 ±3–4 帧、拉伸 0.7–1.3、电平 ±3dB）
- λb 8 → 20，只压边界
- 训练对加「长音拉伸」缺陷（1.5–6×）以处理本文件的电音问题

## 追加：乐句结尾「卡」声（2026-11-15）
根因：模型装配路径**没有应用 OpenUtau envelope**（legacy 由 MelOverlapAccumulator 施加），
最后音符的 p4 收尾缺失，音频以满幅度被时长对齐硬截断（仅剩 5.8ms 边缘淡出）→ click。

修复：`renderer._apply_envelope_gain` 在模型装配后按帧施加每个音素的 envelope 增益
（log-mel 域加 ln(gain)，gain=0 → 1e-4），与 legacy 语义一致。

实测同句（いわない）：
- 修复前缓存：最后 5ms RMS 0.0866，满幅度截断
- 修复后：最后 5ms RMS 0.0034，尾部自然衰减（legacy 0.0002）
- 仍残留：结尾前 ~15ms 一个 vocoder 瞬态（max step 0.11，legacy 0.033），待下一步处理

A/B：`listen_test/click_ab/iwanai_before_after_legacy.wav`（前→修复后→legacy）
