# P0.3 前提诊断 — 第一份实测（2026-11-14）

## 结论（先看）

| 臂 | 口径 | pooled ratio = median(boundary \|Δmel\|) / median(interior \|Δmel\|) |
|---|---|---|
| (a) **真实录音** | OpenCpop 12 例 × 四类硬边界，±50ms | **1.608** |
| (c-donor) **真实装配算子 + 异源片段** | 同歌手另一首歌的同音素片段，overlap≈83ms | **1.794** |
| (c-self) **真实装配算子 + 完美源** | 目标句自己的片段，overlap≈83ms | **1.580** |
| (b) 当前 V2 渲染 | t44 旧口径（边界定义/窗宽不同） | **0.808**（不可直接比） |

**在实测 83ms overlap 下，装配算子把边界比做到 1.58–1.79，与真实录音 1.608 吻合。
因此「装配算子过度平滑边界」这一假设未获支持。** t44 的 0.808 不能直接与 1.608 相减：
它的边界定义、窗宽与内部基线都与本测量不同，且它测的是完整 V2 渲染而非算子本身。

**当前判定：P0.3 未闭合。** 三条臂里 (b) 仍缺同口径数据；在此之前不得把主目标改成
"恢复字头瞬态"，也不得宣布边界假设作废。

## 方法（可复现）

- 规范前端：`backend/wav2mel.py`，与 `diffical_new/backend/vocoder/wav2mel.py` **逐字节相同**
  （sha256 `c5a0816319b9963ffc1ec8724491976e8c37d6283f563a2383af292fba400f41`）。
- hop 512 / 128 bins / fmin 40 / fmax 16000 / n_fft=win=2048 / 自然对数 / `center=False`。
- 帧率 86.1328 fps，frame = 11.610 ms。
- 指标：`Δmel[t] = mean_b |mel[:,t] - mel[:,t-1]|`；边界窗 ±4 帧（±46.4ms）；
  内部 = 去掉边界窗与首尾 10 帧；静音帧（全 bin 最大 ≤ −19，即 ln 域地板附近）剔除。
- 边界时刻来自 OpenCpop `ph_dur`（**秒**，其求和 = wav 时长，已核验）；12 例四类各 3，
  清单 `data/opencpop/selected12.json`。

命令：

```bash
python3 tools/opencpop.py        # 选 12 例 -> data/opencpop/selected12.json
python3 tools/make_donors.py 60  # 选 60 条捐赠句 -> data/opencpop/donors.json
python3 eval/p03_real.py         # 臂 (a) -> data/opencpop/p03_real.json
python3 eval/p03_synth.py        # 臂 (c) -> data/opencpop/p03_synth.json
```

装配算子直接 import 旧仓 `diffical_new/backend/overlap.py`（只依赖 numpy），
未复制、未改动。envelope 语义已按 `_integrate_mel_to_phrase_frames` 核对：
`xs = anchor_ms/frame_ms + envelope_x/frame_ms`，即 envelope x 是相对声部锚点的 ms。

## 平滑步骤审计（2026-11-14）

对 `diffical_new/backend/renderer.py` 做调用审计，若生产路径存在 mel 域时间平滑，
它会是 0.808 的最直接解释。结论：**没有任何平滑步骤被调用**。

| 函数 | 位置 | 结论 |
|---|---|---|
| `_smooth_inter_frame_transitions`（Hanning 核 15 帧 ≈174ms） | :1973 | 只有定义，**零调用** |
| `_localized_energy_smooth`（`gaussian_filter1d` σ=2） | :2250 | 零调用 |
| `_smooth_phone_boundaries` | :1464 | 零调用 |
| `_smooth_formant_envelope` | :2296 | 零调用 |
| `energy_smooth` / `formant_smooth_transition` / `frequency_dependent_crossfade` / `spectral_flux`（来自 `mel_concatenate`） | :66-67 import | 仅在 import 行，**零调用** |

生产 mel 路程实际只有：`_process_phones`（逐音素取 mel + `np.interp` 拉伸）→
`_concatenate_mels`（`MelOverlapAccumulator`）→ `_synthesize_per_phone`（一次 vocode）。
这三步里，前两步已被本报告的 (c) 臂覆盖（operators + donor/isolated 源），
**均给出 ≥1.58 的边界比，无 0.808**。

## 三条臂的绝对值拆解（关键）

| | 边界 Δmel | 内部 Δmel | ratio |
|---|---|---|---|
| 真实录音 | 0.4409 | 0.2761 | 1.597 |
| 合成装配（donor @83ms） | — | — | 1.794 |
| **V2 渲染** | 0.3719（真实 ×0.844） | 0.1551（真实 ×**0.562**） | 2.399 |

**边界绝对动态只低了 16%，内部低了 44%。** 比值升高主要来自分母塌陷，不是接缝变糙。

这也解释了 t44 的 0.808 为什么与本测量不一致：t44 量的是**装配后的 mel**（且边界/窗定义不同），
本臂量的是**过完声码器的完整波形**；两者口径不同，不能直接相减。真正可比的结论只有一条：
**V2 的单元内部比真实演唱静了将近一半。**

## 因此（修正版结论）

1. **"病在接缝"**：方向对了一半。接缝确实是问题显形的地方，但**机制不是"过渡被抹平"**，
   而是"**单元内部没有微动态**，于是接缝显得突出"。拼接式合成器的指纹是"内静 + 接缝跳"。
2. **"模型应该学过渡"**：不完整。模型首先要**把单元内部的动态补回来**（0.155 → ≥0.24，
   即真实 0.276 的 ≥85%），同时保持边界绝对动态不高于真实（0.372 → 0.40–0.47）。
   比值 2.40 → ≈1.6 是结果，不是目标。
3. **因此参数化应从"残差"改为"绝对生成"**：内部要整体 +58% 的动态，是全局改写，
   不是局部修补；残差头虽然有同样的函数类，但初始化偏向小修正，会系统性欠拟合这一项。
4. **P0.3 判定**：按 SPEC §0 的预注册判据，`Δ = 2.399 − 1.597 = +0.80 > +0.15`，
   落在"边界过粗糙"分支；但绝对值拆解表明更准确的表述是"**内部过静**"。
   两者都指向"需要整句重写"，因此**主目标保留在边界/单元动态上**，不改为"仅整句粗糙度"。

## 已知局限（不得隐瞒）

1. **donor 臂用的是连续演唱切片**，不是生产里的孤立 CV/VCV 声库采样；音高差、录音差、
   极端拉伸比（生产可达 10×）都未建模。
2. **只测了 mel 域**，未过声码器；波形域/相位问题不在本诊断范围内。
3. 12 例的边界类型覆盖来自 OpenCpop 单女声，代表性有限。
4. 臂 (b) 缺失：要拿真实 V2 渲染，需要 OU phonemizer 级别的音素映射
   （本地中文声库 alias 是 CV 方案，对不上 `ian/iang/iong` 等复合韵母）。
