# Rust backend (work in progress)

Goal: replace the Python backend with a single Rust binary that runs two ONNX models
(assembler + vocoder) and reproduces the current renderer behaviour.

## Status

- [x] Workspace, protocol skeleton later
- [x] Mel frontend parity with Python: `diffical-cli mel-parity golden`
      golden tensors are generated by `tools/dump_golden.py`
      measured max abs diff 9.1e-5, mean 6.2e-7 (log-mel, natural log)
- [ ] oto.ini parsing and source slicing/stretch
- [ ] render request protocol + HTTP server (axum)
- [ ] ONNX pointer + vocoder inference (`ort`)
- [ ] flags / expression curves
- [ ] HN-SEP (export the 57 MB PyTorch model to ONNX first)
- [ ] end-to-end parity harness over real requests

## Parity workflow

```bash
# 1. dump golden tensors from the Python backend
python rust/tools/dump_golden.py

# 2. compare the Rust mel frontend
cargo build --release
./target/release/diffical-cli mel-parity golden
```

The golden directory holds raw little-endian f32 arrays and a params.json so the Rust side
does not depend on numpy or .npy parsing.

## Not planned
